# Spec: S6.11 Captura directa desde cámara completa

> Spec-Driven Domain. Esta spec es la fuente única que alimenta los tests y las auditorías.

- **ID / tarea:** S6.11
- **Contexto (módulo):** `frontend/features/capture`, `invoice_intake`, `invoicing`
- **ADR relacionados:** ADR-0002, ADR-0015
- **Estado:** aprobada por Julio (2026-08-13)

## 1. Problema y valor de dominio

La pantalla principal de captura debe mantener sus decisiones de negocio visibles: factura recibida o emitida,
tomar una foto y subir un archivo. La vista de cámara necesita todo el espacio del móvil para encuadrar una
factura de cerca, pero no debe sustituir el panel principal ni añadir una revisión de foto que frene el flujo.

## 2. Lenguaje ubicuo

- **Panel de captura:** pantalla inicial con selector Recibida/Emitida, botón "Tomar foto" y botón "Subir
  archivo".
- **Cámara completa:** pantalla temporal a ventana completa que se abre solo al pulsar "Tomar foto".
- **Capturar foto:** pulsación consciente dentro de la cámara que toma el frame y lo envía directamente.
- **Procesando factura:** estado posterior al envío que espera al OCR y desemboca en la comprobación de datos.

## 3. Comportamientos

### C1 - El panel conserva las acciones principales
- **Given** un usuario entra en `/capturar`.
- **When** aún no abre la cámara.
- **Then** ve Recibida/Emitida, el botón "Tomar foto" y el botón "Subir archivo"; no se solicita permiso de
  cámara ni aparece un botón llamado "Abrir cámara".

### C2 - Tomar foto abre la cámara completa
- **Given** el panel de captura.
- **When** pulsa "Tomar foto".
- **Then** se solicita la cámara y aparece una pantalla completa con vista previa, guía A4 vertical grande,
  "Capturar foto" y "Cerrar cámara".

### C3 - Capturar foto envía directamente
- **Given** una cámara preparada.
- **When** pulsa "Capturar foto".
- **Then** se apaga la cámara, se toma y normaliza el frame, se envía la imagen a la empresa autorizada con la
  dirección elegida y no se muestra una revisión intermedia con "Usar esta foto".

### C4 - El envío comunica procesamiento y abre comprobación
- **Given** una foto enviada desde cámara o selector de archivo.
- **When** la API acepta el fichero.
- **Then** ve "Procesando factura..." mientras el OCR termina y después llega al panel de comprobación ya
  existente; no se anuncia éxito antes de que haya datos de revisión.

### C5 - Fallos no pierden la salida segura
- **Given** un error de cámara, normalización, subida o OCR.
- **When** ocurre el fallo.
- **Then** se apaga cualquier cámara activa, se muestra un mensaje corto y el usuario puede volver a tomar o
  subir otra foto; nunca se sube una foto sin pulsar "Capturar foto" o seleccionar archivo.

## 4. Invariantes

- La cámara solo se abre mediante "Tomar foto" y solo dispara mediante "Capturar foto".
- Recibida/Emitida elegida en el panel viaja hasta la comprobación.
- Un `user` solo sube a su empresa; un `tenant_admin` elige empresa antes de capturar o subir.
- La cámara se apaga antes de enviar y ningún resultado asíncrono antiguo puede reemplazar una captura nueva.
- Se conservan antivirus, JPEG normalizado, autorización y espera de OCR existentes.

## 5. Fuera de alcance

- Revisión manual de la foto antes de enviar.
- Captura automática, selección manual de lentes y cambios en OCR.

## 6. Verificación

- Tests de panel inicial, apertura de cámara completa, envío directo desde cámara, subida de archivo, espera
  OCR y limpieza de stream.
- Prueba manual Android/iPhone: permiso, foto cercana, cerrar, denegar permiso y selector de archivo.
