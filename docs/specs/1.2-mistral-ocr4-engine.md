# Spec: 1.2 Motor de lectura OCR — Mistral OCR 4 (cabeza de serie del bench)

> Spec-Driven Domain. Esta spec es la **fuente única** que alimenta los tests (TDD) y las auditorías.
> Si algo no está aquí, no se implementa. Aprobada por Julio antes de escribir tests.

- **ID / tarea:** 1.2 (Fase 1, POC OCR) — arranque de la capa de motores de lectura
- **Contexto (módulo):** ocr (`backend/src/ocr/engines/`)
- **ADR relacionados:** ADR-0007 (motor OCR ganador, se decide por bench), ADR-0010 (verificación "tipo DNI")
- **Estado:** aprobada por Julio (2026-07-01)

## 1. Problema y valor de dominio
La Fase 1 compara varios motores OCR con las 20 facturas reales y decide el ganador **por datos** (ADR-0007).
Para poder benchmarkear hace falta una **interfaz común de motor** y el primer motor implementado. Julio decide
que **Mistral OCR 4** (lanzado 2026-06-23; id de modelo `mistral-ocr-4-0`) entra como **cabeza de serie** (motor
de lectura por defecto), sin saltarse el método: el ganador formal lo sigue fijando el bench.

Valor: dado un fichero de factura (imagen o PDF), obtener de forma asíncrona un **resultado normalizado**
(texto/markdown + metadatos + respuesta cruda para el scorer del bench), con **errores tipados** en vez de
excepciones crudas del SDK, para que el orquestador del bench pueda enrutar y, en el futuro, hacer fallback a
otros motores.

## 2. Lenguaje ubicuo
- **Motor de lectura (`OcrEngine`)**: componente que, dado un documento, devuelve un `OcrResult`. Interfaz común
  a todos los candidatos del bench (Mistral, DocIntel, PaddleOCR, Qwen...).
- **`OcrResult`**: resultado normalizado, independiente del proveedor: `text` (markdown), `pages`, `usage` y
  `raw` (respuesta cruda del proveedor, que el scorer del bench podrá explotar sin perder nada).
- **Cabeza de serie**: motor por defecto del bench; no es "ganador por decreto" (eso es ADR-0007 tras medir).

## 3. Comportamientos (criterios de aceptación)

### C1 — Extraer de un documento devuelve un resultado normalizado
- **Given** un motor Mistral OCR 4 y una factura (imagen o PDF) existente
- **When** se llama a `extract(file_path)`
- **Then** devuelve un `OcrResult` con `engine="mistral-ocr-4"`, el `model` usado, las páginas con su `markdown`,
  el `usage` y la respuesta cruda en `raw`; `result.text` concatena el markdown de las páginas

### C2 — Sin API key, el motor no se construye a medias
- **Given** una API key vacía o ausente
- **When** se instancia `MistralOcr4Engine`
- **Then** lanza `MistralOcrError` con un motivo claro (no se crea un motor que fallará opaco después)

### C3 — Un fichero inexistente da error tipado
- **Given** una ruta que no existe
- **When** se llama a `extract`
- **Then** lanza `MistralOcrError` (no un `FileNotFoundError` crudo)

### C4 — Un fallo del proveedor se envuelve en `MistralOcrError`
- **Given** que la llamada al SDK de Mistral falla (credenciales inválidas, timeout, error de API)
- **When** se llama a `extract`
- **Then** lanza `MistralOcrError` que **encadena** (`from`) la excepción original; nunca propaga la excepción
  cruda del SDK hacia el llamador

### C5 — El tipo de documento se traduce al formato de Mistral
- **Given** un PDF o una imagen (`.pdf`, `.jpg/.jpeg`, `.png`)
- **When** se prepara la petición
- **Then** un PDF viaja como `document_url` y una imagen como `image_url` (base64 data URI); un tipo no
  soportado lanza `MistralOcrError`

### C6 — Procesar varios documentos
- **Given** una lista de ficheros
- **When** se llama a `batch_extract`
- **Then** devuelve un `OcrResult` por documento (concurrencia local con `asyncio.gather`; NO es el endpoint
  batch de Mistral, que se evaluará en el bench si compensa)

### C7 — El registro entrega Mistral OCR 4 como motor por defecto
- **Given** la configuración con `MISTRAL_API_KEY`
- **When** se pide el motor de lectura por defecto del bench
- **Then** se obtiene un `MistralOcr4Engine` (cabeza de serie)

## 4. Invariantes y reglas de negocio
- **Ganador por bench, no por decreto:** Mistral OCR 4 es el motor por defecto/cabeza de serie; la elección
  formal del motor de producción es ADR-0007 y se decide con las 20 facturas. La interfaz `OcrEngine` está
  pensada para que otros motores entren igual y para permitir fallback en el orquestador del bench.
- **Frontera de errores:** ninguna excepción cruda del SDK de Mistral cruza la frontera del motor; todo fallo
  sale como `MistralOcrError` (subclase de `OcrError`).
- **Nada se pierde:** `OcrResult.raw` conserva la respuesta completa del proveedor (bloques, bounding boxes,
  confidencias de OCR 4) para el scorer del bench; el parseo tipado fino se hará al construir el scoring.
- **Sin red en CI:** los tests mockean el cliente de Mistral; jamás llaman a la API real.
- **Id de modelo correcto:** por defecto `mistral-ocr-4-0` (verificado contra la documentación de Mistral).

## 5. Casos límite y errores
- API key vacía/`None` → `MistralOcrError` en construcción (C2).
- Fichero inexistente o tipo no soportado → `MistralOcrError` (C3, C5).
- Fallo de red/credenciales/timeout del SDK → `MistralOcrError` encadenado (C4).
- Respuesta sin páginas → `OcrResult` con `pages` vacío y `text` vacío (no revienta).

## 6. Fuera de alcance (no-objetivos)
- El **bench completo** (scoring por campo, ground truth, comparación entre motores): tarea siguiente. Aquí
  solo va la interfaz + el primer motor.
- Los **otros motores** (DocIntel, PaddleOCR, Qwen, Gemini/Claude/GPT como 2º lector): se añaden después con la
  misma interfaz.
- El endpoint **batch** de Mistral y el parseo tipado fino de bloques/bbox: se abordan en el bench si aportan.
- Integrar la verificación "tipo DNI" (`verification.py`) sobre los campos: va en el bench/worker, no aquí.
